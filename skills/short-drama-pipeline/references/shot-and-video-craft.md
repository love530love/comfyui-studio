# 镜头语法、视频提示词与审阅

改编自 Toonflow v118workflow 的 shotCraft、videoPromptCraft、storyboardTable、videoProduction（MIT，HBAI-Ltd/Toonflow-app，commit eecf515）。只保留能落到本机 H3 / Wan / 剪辑链路的规则；画布、节点与平台工具不迁移。

## 1 镜头选择

先问"这一镜给观众什么新信息"，再选景别、角度、运动。地点/时间切换、主体转移、重要动作节点、有意义的景别变化才切镜；同一画面的微表情和连续对白不必切碎。

| 景别 | 适合承担的信息 |
| --- | --- |
| EWS 大远景 | 定场、规模、人与环境的悬殊 |
| WS 远景 | 行进路径、人物距离、空间引入 |
| FS 全景 | 登场、完整肢体动作、人与道具关系 |
| MS 中景 | 对话、上肢动作、双方关系 |
| MCU 近景 | 情绪变化、手脸同框 |
| CU 特写 | 决定、细微反应、关键线索 |
| ECU 大特写 | 决定性细节，全片克制使用 |
| OTS 过肩 | 对话、压迫感、视线归属 |

- 定场 1–2 镜完成：远景缓推同时交代环境与主体，或环境全貌接主体全景。
- 连续三个同景别且无信息或关系变化，检查是否该合并或换景别。
- 角度说明机位相对主体的观察位置，运镜说明摄像机随时间怎样移动；俯仰本身不是运动。
- 一个镜头只安排一个主要运镜，写清起幅、路径、落幅；不把推、拉、摇、环绕无依据堆进同一短镜。
- 一镜到底只用于已确认的连续空间或连续动作，写清沿途出现的新信息。

## 2 空间基准

每场第一次清楚交代空间后，立刻建立基准并写进导演规划或 `09_logs/agents.md`：

```text
场 1 / 基准版本：分镜 vN
陈默：右前，3/4 正面朝左，看向门口；右手提冰袋
变化点：s003 左手举手机照明；s007 放下冰袋（state_change 镜）
```

- 位置用九格：左前/中前/右前/左中/中中/右中/左后/中后/右后；前后指距镜头深度，高低另写。
- 对话/对峙先定互动轴线：左侧人物向右看，右侧人物向左看。走位、转头、跨轴必须在画面里看见建立过程，后续沿用新基准；机检见 `continuity-control.md`。
- 相邻镜核对角色位置、动作完成度、持物手、道具归属、眼线、服装与伤势状态。
- 在场人物必须在相邻镜或同片段有可理解落点：背景、局部、过肩、反应镜或已建立的画外声源，不能凭空消失。

## 3 表演落地

情绪写成可见动作，不写情绪词。

| 表演目标 | 可见依据 |
| --- | --- |
| 克制愤怒 | 下颌绷紧、握持渐紧、视线不移、出声前短停顿 |
| 悲伤强忍 | 眨眼变慢、呼吸中断、嘴唇收紧、低头避开对视 |
| 试探迟疑 | 话前看向对方、手势停在半途、重心未完全前移 |
| 决意 | 视线稳定、动作收束、姿态明确、语尾落定 |
| 轻蔑 | 已确认的冷笑、抬颏、短暂斜视与互动距离 |

听者反应用眼神、呼吸或小幅姿态即可，不抢说话人的焦点；群演只用遮、瞥、垂、攥等微动作，不加台词。

## 4 台词与时长

- 本机默认 4.5 字/秒（见 `failure-modes.md` F04）。慢速表演可选 3 字/秒（陈述）或 2 字/秒（深情、虚弱）；采用前说明它对镜长和片段数的影响。
- 最小镜长 = 字数 ÷ 语速 + 每处明显停顿 0.3–0.5 秒 + 首尾余量合计约 1 秒；相同停顿不重复累计。
- 超过 20 字的连续台词/VO 按语义停顿拆连续镜头，改变景别或切听者反应镜，声音仍归原说话人；不能让模型每镜重念整句。
- 动作密度：2–3 秒约 1 拍，4–6 秒约 2 拍，7 秒以上约 3 拍。一拍 = 一项物理动作、一次主要运镜或一句短台词。
- 无信息静态镜约 6 秒就检查是否拖沓；有意保留的长镜必须靠表演或运镜推进。

## 5 视频提示词契约

所有模式共用：

1. 一单元一提示词：一个已确认镜头（或已确认的连续片段），不跨镜合并，不借模板删镜。
2. 参考图负责身份/外观与构图；参考顺序与真实输入一致，缺图不虚构编号。
3. 台词保留原语言原文，逐字不译；对白只有说话者口型对应，OS/VO 明确"人物嘴部不动"。
4. 动作写可见过程、速度、结束状态；情绪通过姿态、视线、呼吸体现，不新增剧情动作。
5. 声音写具体声源（风穿窗缝、杯底触桌、冰袋滴水），默认不配乐。
6. 继承已确认场景光照与风格；不用 4K、cinematic、masterpiece 堆砌。
7. 时长写在节点配置，正文不写秒数；单镜 3–5 秒，片段上限 15 秒。

### 模板 A：单首帧（本机 H3 / Wan I2V，默认）

```text
[已确认的风格短句]
[角色名 + 首帧可见的少量识别特征] begins in [首帧确切状态],
then [已确认动作、节奏与情绪演进], ending in [已确认结束状态].
[已确认的场景、道具与空间关系；不写未确认布景]
[仅必要时写已确认的光照约束]
"[原语言完整台词]" — [说话者]（对白 / OS / VO）。
[具体环境声与动作声；无台词时写 No dialogue]
Captured in [起始景别与角度], [一个连续运镜及落点], as one continuous shot.
```

本机 H3 的原生音轨只用于环境声与动作声；对白配音在后期 TTS 混入，提示词不要求角色开口说台词，除非已实测该模式能稳定复现中文口型。

### 模板 B：多参考输入（节点确实支持多图时）

```text
将图1中的[稳定身份特征]定义为<主体1>；
将图2中的[空间锚点]定义为<场景1>；
将图3中的[结构特征]定义为<道具1>。

[有则逐字保留：承接上镜的已确认说明]
镜头1：[景别 + 一个主要运镜]。<主体1>在<场景1>的[位置]面朝[方向]，
[可见动作与表情演进]，与<道具1>[真实互动]。
<主体1>说 {原台词}，只有他口型对应；<具体声源>。
[已确认风格短标签]；同一人物、服装与道具，动作连贯，无分身、水印、画面文字。
```

标签是提示词内部指代，不是节点 id；一个参考绑定两三个核实过的稳定特征，不堆形容词。

### 模板 C：首尾帧五段式（模式支持且确实需要尾帧时）

- Visual：首帧状态、人物位置与姿态、场景与道具。
- Motion：`0s–t1s` 第一段动作与状态变化，`t1s–末尾` 后续动作到尾帧状态；每段至少 1 秒、连续覆盖总时长。
- Camera：起始景别与角度，一条连续运镜路径，`single continuous take, no cuts`。
- Audio：台词区间、说话者、OS/VO 口型状态、具体声源。
- Narrative：已确认的戏剧节拍，不新增事件。

首尾帧的位移和形变必须在时长内可完成；不得用"无切镜"把两场硬拼成一个空间。

## 6 三点停与验收

- 准备停：提示词、模型/模式、参数、单元数量与范围确认后才生成；确认准备不等于授权生成。
- 结果停：请求成功不等于视频成功；逐条验收，保留候选与失败清单。
- 选用停：确认采用或重做范围后写回清单，未选候选不删除。

验收逐项看实际媒体：

- 身份、服装、道具与资产一致，基础态/衍生态正确；
- 动作与镜头符合分镜，无关键事件缺失；
- 台词完整、说话者正确、OS/VO 无口型、声源相符；
- 左右与视线、持物手、动作进度连续，尾帧与下一镜首帧能接上；
- 时长、比例、清晰度可用，首尾无截断或多余尾段；
- 文件可读且对应正确镜号。无法播放或读音轨时标"待用户核验"，不拿路径和成功状态冒充已看。

## 7 审阅 rubric

| 原则 | 核验方法 |
| --- | --- |
| R1 真实引用 | 片段引用与资产、采用文件逐项对应；无虚构 id、无错位、无未绑定关键角色 |
| R2 忠实剧本 | 台词、事件、顺序逐条比对；无漏词、改词、漏场、新增事件 |
| R3 可见可听 | 画面动作、声源、表演细节可执行；不写"很悲伤/烘托气氛" |
| R4 状态正确 | 对照父资产、剧情状态与采用版本；不把同一人的两态当两人 |

问题按严重/中等/轻微记录，格式：严重程度、镜号、原文或引用、影响、可选修订。只列问题，同类轻微合并；检查通过不等于用户已确认。

## 8 预演（previs）

多人物走位、复杂机位、跨轴、狭窄空间（楼道、厨房、桌边对峙）在 G2 前做一次预演，产物写 `01_series/director/epNN_previs.md`：

- 每场九格基准、轴线侧与变化点；
- 每镜机位高度、等效焦距、起幅/落幅、主体路径、进出画方向；
- 按播放顺序拼一张低模/流程图接触表，标出每镜的起终状态。

工具优先级：Blender MCP（本机现成）> 浏览器 3D 导演台 demo（纯前端、MIT，快速摆位时用，安装前先征得同意）。预演不是关键帧，不参与 G3 签字，不替代 G2；它只用于提前发现站位、轴线与机位冲突。

## 9 与分镜字段的映射

- `shot_type`、`camera` 承载景别与运镜；需要预演时把高度、焦距、起落幅写进 `camera`，如 `1.6m eye level, 50mm, pan right 45°`。
- `beat` 保持单拍；超过 20 字的台词拆镜或在 `dialogue` 标出声音延续范围。
- `state`、`transition`、`axis_side` 仍以 `continuity-control.md` 为准，本文不新增字段。
- 审阅发现的问题写 `09_logs/agents.md`，不改 shotlist 原文；返工范围经确认后才动分镜。
